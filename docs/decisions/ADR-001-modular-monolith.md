# ADR-001：模块化单体与 PostgreSQL 任务队列

- 状态：accepted
- 日期：2026-08-09
- 决策者：项目维护者
- 替代：无
- 被替代：无

## 背景

MVP 每天处理 1～3 条短视频，需要 API、后台长任务、恢复和并行开发，但尚无规模证据支持微服务或独立消息队列。

## 决策

采用模块化单体。FastAPI、Worker 和 React 为独立进程/应用；Python 领域包按职责分层并共享。PostgreSQL 同时保存业务数据和 Job 队列，Worker 通过带租约的原子领取、心跳和有限重试执行任务。单台 Linux 使用 Docker Compose 部署。

只有在可观测数据证明 PostgreSQL 队列无法满足吞吐、隔离或可靠性目标后，才另立 ADR 评估消息队列或服务拆分。

## 候选方案

- 微服务加专用消息队列：扩展边界清晰，但显著增加部署和一致性成本。
- 单进程同步执行：实现最少，但无法可靠处理媒体长任务和进程恢复。

## 影响

开发、事务和本地部署更简单，模块仍可由冻结接口并行开发。代价是 API 与 Worker 共享数据库和发布节奏，必须通过包边界、任务租约和集成测试控制耦合。
