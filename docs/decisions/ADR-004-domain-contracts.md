# ADR-004：M1 领域契约与错误分类

- 状态：accepted
- 日期：2026-08-09
- 决策者：项目维护者
- 替代：无
- 被替代：无

## 背景

数据库、Worker、供应商适配器和 HTTP API 将并行开发。若各模块自行定义状态、标识和失败语义，会使恢复、幂等与血缘行为无法一致验证。

## 决策

公共契约放在不依赖 FastAPI、PostgreSQL 或供应商 SDK 的 Python 包中。领域值对象使用不可变数据类、递归冻结的 JSON 元数据和字符串枚举；跨进程持久化使用 UUID、UTC 时间与十六进制 SHA-256。Source 保存内容摘要、摘要说明与结构化引用片段，Artifact 引用来源 ID、片段 ID 和当时的来源内容摘要。

项目状态只能通过显式转换表迁移，并携带单调 `revision` 供 Repository 乐观并发更新。失败阶段由进入失败前的项目状态推导，调用者不得指定；生成失败恢复到生成，发布失败恢复到已批准并创建新的发布执行。Provider 只实现 `generate`，Publisher 实现 `validate`、`publish`、`status` 和 `metrics`；幂等键属于不可变 Publication，协议使用同步调用，Worker 负责超时、重试和持久化编排。

错误分为可重试外部失败、永久业务失败、适配器契约失败和非法状态转换。只有可重试错误可进入自动重试策略，发布重试仍必须复用幂等键并先查询状态。

## 候选方案

- 各应用维护自己的 Pydantic 模型：HTTP 开发直接，但领域约束容易分叉。
- 在契约中使用异步协议：适合网络调用，但会把运行时模型扩散到领域层，MVP 由 Worker 在线程或进程边界处理阻塞调用更简单。

## 影响

后续模块可围绕稳定、轻量的类型并行开发和契约测试。新增状态或破坏性字段变更需先更新本 ADR 或建立替代 ADR，并同步迁移与上下游测试。
