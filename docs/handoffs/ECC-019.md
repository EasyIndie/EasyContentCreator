## 已完成

- `JobStore` 提供 enqueue、原子 claim、heartbeat、succeed 和 fail，所有租约操作失败关闭。
- claim 使用 PostgreSQL `FOR UPDATE SKIP LOCKED`，同时支持到期 queued 与租约过期 running Job。
- attempt 在认领时递增；最终 attempt 的崩溃任务在下一次轮询时标记失败，不会永久保持可认领状态。
- 只有 `RetryableError` 且还有剩余 attempt 时按 retry_at 回到 queued；永久、契约、状态及未知错误直接失败。
- PollingWorker 每轮最多执行一个 Job，未知 kind 失败关闭，同步 handler 执行期间使用独立连接续租。
- 日志不包含 payload 或异常正文，数据库 `last_error` 只保存异常类名。

## 验证证据

- 环境：隔离 Docker `postgres:16-alpine`，数据库 `ecc_test`，测试使用随机 `ecc_test_*` schema。
- 两个真实连接同时认领同一 Job：严格一成功、一空结果。
- 租约到期由另一 worker 恢复且 attempt 递增；旧 worker 的 heartbeat/succeed/fail 全部抛出 LostLeaseError。
- RetryableError 的延迟重试、次数耗尽，以及 Permanent/Contract/State/未知异常失败关闭全部通过。
- Worker 长 handler 期间真实 PostgreSQL heartbeat 至少执行两次并最终成功。
- 针对性测试 12 项通过；Ruff format check、Ruff lint、strict Mypy、文档与 diff 检查通过。

## 决策与偏差

- ECC-017 jobs schema 已完整支持租约语义，未创建 `002`，也未修改 `001_initial.sql`。
- enqueue 的 created/updated 时间使用 PostgreSQL `CURRENT_TIMESTAMP`，available_at 仅控制调度时间。
- Job handler 保持同步协议；后台心跳只负责续租，不改变 handler 的运行时模型。

## 后续执行者须知

- handler 不应捕获并吞掉 RetryableError，否则 Worker 会把正常返回视为成功。
- 租约过期后即使 worker ID 相同也不能提交结果；必须重新 claim 获得新 attempt。
- 发布 handler 重试前仍需查询 Publisher 状态并复用 Publication 幂等键，JobStore 不替代该业务规则。
- `001_initial.sql` 已应用且不可修改；未来 schema 变化只能追加编号迁移。
