## 已完成

- 新增 `POST /projects/{project_id}/generate`，严格校验 Idempotency-Key、非空无重复 Source IDs、模板版本和正预算。
- API 只装配 ECC-025 `GenerationRequestRepository`；同 key/同摘要返回原 Job，同 key/异摘要返回稳定 `409 idempotency_conflict`。
- Worker 启动时注册 ECC-026 `FactCardGenerationHandler` 与确定性 Fake Provider，不复制 SQL 或恢复 auto-succeed。
- 新增最小 `ECC_ARTIFACT_ROOT` 设置，默认 `artifacts/`；Fake 文件先写入该根目录，再由 handler 原子提交数据库终态。
- 复用既有项目 review API，从 `review_required` 人工批准到 `approved`。

## 验证证据

- 环境：隔离 Docker `postgres:16-alpine`、随机测试 schema、FastAPI TestClient、临时 Artifact 根目录，无网络和真实凭据。
- API 同键重放返回同一 Job 且数据库仅一条 reservation/Job；同键异摘要固定 409；缺 header、空/重复 Source、空模板和非正预算均 422。
- 成功链路从 draft 经 Worker 到 review_required，再经 review API 到 approved；Artifact citation 精确回溯 Source、Excerpt 和 Source SHA-256。
- 使用相同 reservation 和 Fake 请求在第二临时根目录重建，产物字节完全一致。
- 一次 RetryableError 仅重排原 Job，下一 attempt 复用同 reservation/version 并成功。
- 空 excerpts 永久证据失败进入 generation-failed；新 key 恢复预留相同逻辑 Artifact ID 的 version 2 并成功。
- 模拟 Worker 认领后进程退出，租约到期由新 Worker 恢复同一 Job，最终只有一个 Artifact。
- E2E 5 项、完整回归 108 项通过；Ruff format/lint、strict Mypy、文档与 diff 检查通过。
