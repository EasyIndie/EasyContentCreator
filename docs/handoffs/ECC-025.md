## 验证证据

- 环境：隔离 Docker `postgres:16-alpine`，数据库 `ecc_test`，随机 `ecc_test_*` schema。
- 同 key 双连接并发：两调用返回同一 reservation/job/version 1，数据库只有一条 request 和 Job。
- 异 key 双连接并发：一项成功、一项因项目已 generating 失败，未消耗重复版本。
- 同 key 异摘要：固定冲突且项目、request 与 Job 无额外变化。
- generation-failed 恢复：相同 UUIDv5 Artifact ID，新 reservation/job 使用 version 2。
- 后半程故障注入：`generation_requests` INSERT 失败后，项目更新与 Job INSERT 全部回滚。
- 历史兼容：已有 Artifact version 7 时预留 version 8；仅应用 001 且含 project/job/artifact 数据的数据库升级 002 后数据完整保留。
- canonical hash 使用固定 golden digest，并分别覆盖 project、Source IDs、template version、budget units 变化。
- 针对性 generation/Fake/adapter/Repository 测试 28 项通过；完整 82 项测试通过；Ruff format/lint、strict Mypy、docs/diff 均通过。

## 决策与偏差

- 按 ADR-005 保持单活生成；没有为了“并发版本”放宽 generating 状态限制。
- reservation 同时查询已落库 Artifact 和全部 reservation 的最大版本，因此失败或未完成版本不会被复用。
- 请求事务直接拥有 generation request 与 Job 插入，未串联多个各自提交的 Repository。
- 未修改 `001_initial.sql`、冻结领域模型、API、Worker 或 handler 完成协议。
- 既有 Job 测试把模块级时钟固定为导入时间后 1 秒；按默认文件顺序执行全套测试超过该窗口时可能触发 `updated_at >= created_at` 的时间敏感失败。本任务未越界修改 ECC-019 测试，完整回归将 Job 测试置前后 79 项全部通过；建议由后续测试加固任务消除该时钟假设。
