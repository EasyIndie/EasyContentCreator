## 已完成

- 删除 Worker 对已注册 handler 的自动 `succeed` 路径；handler 返回后只调用 `require_terminal` 验证 `succeeded|failed`。
- handler 返回但 Job 仍非终态时以 `AdapterContractError` 失败关闭；未知 kind 仍由 Worker 直接永久失败。
- `GenerationRequestRepository.get_by_job_id` 提供 reservation/Job 唯一查询，不重新分配 Artifact 身份或版本。
- `GenerationTerminalRepository` 在一个事务内锁定并核对 live lease、reservation 与项目 revision/status。
- 成功事务原子写入不可变 Artifact、血缘、citations、FACT_CARD current pointer、项目 `review_required` 与 Job `succeeded`。
- 永久失败事务保存候选 Artifact（若存在）、不移动 pointer，并原子提交项目 generation-failed 与 Job failed；只持久化异常分类。
- `FactCardGenerationHandler` 注入 Provider 与 UTC clock，装载全部 Source、构造稳定 citations，并让 RetryableError 传播给 Worker 重排原 Job。

## 验证证据

- 环境：隔离 Docker `postgres:16-alpine`，真实双连接租约与随机测试 schema。
- 成功终态提交后 Artifact、citations、pointer、项目和 Job 同时可见；Job 不可再次 claim，重复终结因失租拒绝且 Artifact 不重复。
- 成功事务要求 Source key 精确等于 reservation 的全部 source_ids，并在锁内重建全部稳定 citations；缺失、额外、替换 Source 或 citations 子集均整笔拒绝。
- ArtifactRepository round-trip 证明成功 Artifact 的 citations、metadata 与 lineage 完整保留。
- 永久证据失败保留候选 Artifact，pointer 保持为空，项目与 Job 同时失败。
- 永久失败在已有 FACT_CARD pointer 时保持旧 pointer；中途故障和项目 revision/status 不匹配均无部分写入。
- 项目 UPDATE 前故障注入证明 Artifact/citations/pointer 等前序写入全部回滚，Job 保持 running。
- 提交前崩溃以未调用终态模拟，租约到期后由另一 Worker 认领同一 Job/reservation；旧 Worker 终结无写入。
- handler 在终态前异常退出时 Worker 不做非原子失败提交，Job 保持 running，租约到期后可恢复。
- handler 覆盖 Provider 永久失败、Source 缺失与空 excerpts；终态提交后再抛异常不会破坏 succeeded。
- error class 仅接受最长 128 字符的安全类名；caplog 与数据库断言异常正文、Source 正文、payload 和 secret 不泄漏。
- 提交后崩溃以终态已提交后停止模拟，Job 不可重领或重复写 Artifact。
- Retryable Fake 首次只把原 Job 排回 queued，项目保持 generating、reservation/version 不变；下一 attempt 成功到 review_required。
- 目标测试 33 项通过，完整测试 103 项通过；Ruff format/lint、strict Mypy、文档与 diff 检查通过。

## 决策与偏差

- 未保留 Worker auto-succeed 兼容路径，也未新增 schema 或修改历史 migration。
- `JobStore.fail` 仍只承担 Worker 的 RetryableError 重排、未知 kind 与 handler 契约违规失败；生成业务永久失败由 terminal Repository 原子处理。
- 将既有 Job 测试的固定时钟裕量由 1 秒调整为 1 分钟，消除全套测试耗时导致的 `updated_at >= created_at` 偶发失败。
- 未实现 ECC-023 API 或请求装配。

## 后续执行者须知

- ECC-023 注册 FACT_CARD handler 时必须传入同一 Worker 使用的 UTC clock 语义和 Provider；不得在 handler 外再次 succeed。
- Provider 文件写入发生在终态事务前；确定性路径允许租约恢复复用，同 reservation 不得生成不同内容。
- 任何新生成 handler 都必须在正常返回前自行提交终态，并接受 `require_terminal` 门禁。
