## 已完成

- `GET /sources/{source_id}` 返回 Source 摘要与按持久化 position 排列的 excerpts。
- `GET /projects/{project_id}/artifacts` 在先确认项目存在后，返回按 kind、Artifact ID、version
  稳定排序的版本摘要。
- `GET /artifacts/{artifact_id}/versions/{version}?project_id=...` 在 Repository 查询中校验项目
  ownership，返回公开 metadata、upstream refs 与 citation 摘要快照。公开 metadata 是失败关闭的
  强类型白名单：`capability`、`template_version`、`parameters.source_ids`；其他持久化字段不出现在
  HTTP 响应中。
- 所有响应模型都排除 `storage_path`；实现不访问 Artifact 文件，测试使用不存在的路径仍可成功读取
  数据库证据。
- Source、Artifact 不存在或 ownership 不匹配均使用冻结的 `not_found` envelope；非法 UUID、
  非法 version 与缺失 query 参数由 FastAPI 返回 422。

  与 `..` 路径；API 仅投影白名单 UUID 字段，不执行路径字符串启发式判断。

## 决策与偏差

- 任务指定的 Artifact 路径没有项目上下文，但验收要求跨项目访问失败关闭，因此增加必填
  `project_id` query 参数，不改变指定 URL path。
- Repository 新增 `get_for_project` 作为最小 ownership 查询；既有 `get` 继续保持兼容并委托该方法。
- 未增加迁移、状态变更、下载能力、文件读取或 Web 代码。

## 后续执行者须知

- ECC-030 调用 Artifact 详情时必须传当前项目 ID；404 不应向用户区分不存在与 ownership 不匹配。
- `metadata` 只公开冻结白名单。扩展公开字段必须先明确类型和无路径语义并补契约测试，不能直接
  恢复任意 JSON 序列化；不得根据其中字段拼接服务器路径或读取文件。
- 若未来需要 Artifact 下载，必须按独立任务设计受控根目录、MIME 白名单与授权边界。
