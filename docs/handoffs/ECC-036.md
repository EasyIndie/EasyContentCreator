## 结果

- `packages/domain/pipeline.py` 提供 PipelineRun/StepRun 显式转换、retry/rerun/invalidation 规则、binding-pinned inputs 与多 output reservations。
- `packages/pipeline/contracts.py` 提供完整 golden `short_video_v1`、全局 logical output 唯一校验、稳定 fanout，以及分离的 StepProducer 和 live-lease terminal handler/port。
- `ArtifactKind` 增加 M2 kinds；既有 `ArtifactRef` 现在明确拒绝 bool version。

## 冻结边界

- M2 StepRun 输入必须以 binding name + LogicalArtifactRef 钉住；binding 与 logical key 均唯一，kind 必须匹配 definition。
- SINGLE 输入 logical key 必须等于 source slot；FANOUT 输入必须从 template 恢复稳定 item key，并受 allowed item 集合约束。定义会拒绝 single/fanout 及 fanout/fanout 的相等或前缀 namespace 交集。
- StepRun 只有 `pending/succeeded/failed/invalidated`；queued/running/retry 继续由 Job 表达。
- StepRun 可预留多个稳定 output item；`asset/{shot_id}` 支持镜头 fanout，`channel/douyin/package` 与 `channel/wechat_channels/package` 独立。
- PipelineRun succeeded 明确表示必需节点已完成且 ReviewBundle ready；approval-triggered package 关联该 run，但不阻塞 run completion。
- StepProducer 不持租约；LeasedStepTerminalHandler 得到 step_run_id/job_id/worker_id 和 terminal port，并拥有唯一终态调用。Worker 不得在其返回后二次 succeed/fail。
- retry 保持同一 pending StepRun/Job/reservation；permanent failure 显式进入 failed；rerun 必须创建新 StepRun/Job/key 并单调增加版本；上游变化可 invalidated succeeded run。
- 局部镜头重做使用 fanout child StepRun：只预留目标 item、保持 logical Artifact ID、仅提升该 item version，并把父 StepRun 全部未受影响 output refs 钉入 canonical spec。
- canonical hash 覆盖 project/run、step kind/version、完整 binding inputs、parameters、profile 与全部 output item identities。
- 本任务没有 migration、Repository、Worker、API 或媒体实现。
