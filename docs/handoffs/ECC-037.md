# ECC-037 交接

## 结果

- `003_pipeline_runs.sql` 追加 definition/run/input、logical artifact stream、StepRun/binding/preserved refs 与多 output reservation schema；M2 Artifact kinds 默认关闭，须按 runbook 在所有旧进程退出后单向激活。
- PipelineDefinitionRepository、PipelineRunRepository 与 StepRunRepository 支持 round-trip、事务 reservation+Job enqueue、同 key/hash 复用、异摘要和活动 fingerprint 冲突。
- definition manifest 与生成 digest 使用同一冻结序列化来源，持久化 round-trip 校验 JSON 表示完全一致。
- 每个 `(project_id, logical_key)` 对应固定 Artifact ID；整步/fanout child rerun 复用 ID，只预留单调版本。数据库唯一约束禁止重复 logical version。
- input/preserved refs 通过 project/id/version/kind/SHA 复合外键固定 ownership；run/step/job/project 与 rerun 父级由复合外键严格绑定；依赖失效按精确 Artifact ref 递归，只更新实际下游 succeeded StepRun。
- definition、绑定、preserved refs、logical streams 和 reservations 不可变；run/step 身份字段不可变，终态 run 禁止新增 StepRun，单值输出的 NULL item key 也保持唯一。

## 事务与并发边界

- reserve 锁 PipelineRun，再对每个 logical stream `FOR UPDATE`；同 key 双连接返回同 StepRun/Job/reservations。
- Job、StepRun、inputs、preserved refs、streams 与 reservations 在一个事务；末端 reservation trigger 注入失败后全部为零。
- Repository 在写入 rerun 前读取父 StepRun，并复用 ECC-036 的完整 rerun/fanout-child 校验。
- 本任务不更改项目状态，不执行 terminal，不 claim Job，不创建下游节点；ECC-038 必须在 live lease 事务中完成这些动作。

## 风险与后续

- 003 的 schema 可与上一应用版本共存，但 M2 kind 激活是单向部署门；操作步骤与回滚边界见 `docs/runbooks/m2-artifact-activation.md`。
- invalidation Repository 只处理已 succeeded 历史；pending Job 的取消/协调属于 ECC-038，禁止从 Worker 外旁路更新。
- PipelineRun/StepRun 的终态原子写、Artifact/current logical pointer 和 downstream reconciler 尚未实现。
