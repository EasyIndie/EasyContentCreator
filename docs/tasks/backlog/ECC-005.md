# ECC-005：CI 与质量门禁

## 目标与背景

建立十分钟内优先反馈的 PR 门禁、完整 CI、安全、文档和夜间工作流，并提供一致的本地验证入口。

## 文件范围

- 允许：`.github/workflows/pr-fast.yml`、`ci.yml`、`security.yml`、`docs-check.yml`、`nightly.yml`，`scripts/verify*`、校验脚本、相关测试、本任务/handoff。
- 禁止：应用业务逻辑、部署与 release 工作流。

## 输入与接口

读取 ADR-003；若 ECC-004 尚未合并，工作流调用约定的 `scripts/verify.sh` 子命令并安全探测缺失技术栈；ECC-004 合并后不得静默跳过已存在技术栈。

## 实施要求

- PR 使用 concurrency 取消旧运行，并行执行 Python、Web、文档与密钥扫描。
- 完整 CI 验证测试、构建、迁移和 Compose 健康；缓存 Python、Node 与 Docker 层。
- 文档校验任务元数据、引用文件、ADR 状态和 Markdown 内部链接。
- 夜间执行慢速媒体与依赖扫描；真实供应商探测仅在显式配置沙盒凭据时运行。

## 验收标准

- 本地统一脚本与 Actions 调用相同命令。
- 人为破坏任务元数据、代码格式或测试时对应门禁失败。
- 工作流无仓库密钥，最小 permissions 明确。

## 验收命令

```bash
bash scripts/verify.sh fast
bash scripts/verify.sh full
bash scripts/verify.sh docs
git diff --check
```

## 风险与回滚

Actions 平台行为需以 PR 运行最终验证；本地通过但远程失败不得标完成。回滚工作流和脚本提交。
