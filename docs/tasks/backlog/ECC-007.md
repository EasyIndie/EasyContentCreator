# ECC-007：Compose 与部署回滚框架

## 目标与背景

建立单机 Linux 的本地 Compose、staging 自动部署、production 审批部署、发布和应用回滚框架。

## 文件范围

- 允许：`compose.yaml`、容器构建文件、`deploy/**`、部署/release Actions、`docs/runbooks/deploy.md`、必要配置样例、本任务/handoff。
- 禁止：应用业务逻辑、通用 CI 工作流、现有 ADR。

## 输入与接口

读取 ADR-001、ADR-003；依赖服务提供 `/health`，镜像由 `REGISTRY_IMAGE` 与不可变 `IMAGE_DIGEST` 指定。GitHub 环境名固定为 `staging`、`production`。

## 实施要求

- Compose 包含 api、worker、web、postgres 健康和持久卷，不含明文凭据。
- staging 在 `main` 镜像构建后自动部署；production 只由版本发布触发且要求 Environment 批准。
- 部署脚本获取锁、验证备份、拉取摘要镜像、迁移、启动并 Smoke Test；失败恢复上一摘要。
- release 生成 SemVer tag、GitHub Release、变更日志、SBOM 和镜像元数据；服务器不现场构建。
- Runbook 列出所需 Secrets、服务器准备、首次部署与恢复步骤。

## 验收标准

- `docker compose config` 无错误且本地健康测试通过。
- 部署脚本在 Fake 远端或测试模式验证锁、失败停止和上一镜像回滚。
- Actions 使用最小权限且不输出 Secrets。

## 验收命令

```bash
docker compose config
bash deploy/tests/test-deploy.sh
git diff --check
```

## 风险与回滚

真实 GitHub Environment、镜像仓库和服务器凭据需维护者配置；缺失时仅阻塞真实部署验收。回滚至上一镜像，脚本改动可回滚提交。
