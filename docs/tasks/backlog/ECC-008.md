# ECC-008：并行协作与交付演练

## 目标与背景

用两个互不冲突的低风险任务验证任务领取、独立 Worktree、Draft PR、CI、Squash、handoff、staging 和回滚的完整协作链路。

## 文件范围

- 允许：新增两份演练子任务及其限定文件、对应测试/handoff、`docs/iterations/M0-drill.md`、本任务/handoff。
- 禁止：修改已接受 ADR 或绕过质量/生产审批门禁。

## 输入与接口

仅在全部依赖 completed 后进入 Ready。两个子任务固定为：API `/version` 返回构建版本；Web 页展示同一构建版本。接口响应为 `{ "version": string, "commit": string }`，由构建环境注入，缺省为 `dev`/`unknown`。

## 实施要求

- 两个执行者使用独立 Worktree 和分支，分别提交 Draft PR 与 handoff。
- 先合 API，再基于更新后的 `main` 合 Web；记录冲突、首次 CI 时间、返工和模型升级。
- 合并后部署 staging 并验证页面与 API 版本一致；随后在测试模式演练回滚上一镜像。
- 复盘只提出有证据的流程调整，不扩展产品能力。

## 验收标准

- 两项 PR 均通过必需检查并 Squash 合入，任务与 handoff 完整。
- staging Smoke Test 证明 API/Web 构建版本一致，回滚演练成功。
- M0 复盘记录周期、反馈时间、冲突、首次通过率、部署和恢复结果。

## 验收命令

```bash
bash scripts/verify.sh full
bash scripts/verify.sh docs
bash deploy/tests/test-deploy.sh
git diff --check
```

## 风险与回滚

GitHub 或 staging 尚未配置则移动 blocked 并写明外部解除条件，不用本地结果冒充远程验收。应用变更可回滚对应 Squash，环境按 Runbook 回滚。
