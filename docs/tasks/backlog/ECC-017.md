# ECC-017：PostgreSQL schema 与领域 Repository

## 目标与背景

为冻结的 ContentProject、Source、Artifact 建立首个 PostgreSQL 持久化切片，并为后续 Job、审核和证据规则提供向前兼容表结构。

## 文件范围

- 允许：`migrations/**`、`packages/domain/repositories.py`、`packages/domain/__init__.py`、`apps/common/database.py`、`tests/test_repositories.py`、`tests/conftest.py`、本任务与 handoff。
- 禁止：`apps/api/**`、`apps/worker/**`、Provider/Publisher、Web、CI/部署与已接受 ADR。

## 输入与冻结接口

- 遵守 ADR-004：枚举为字符串、时间为 UTC、元数据为 JSONB、Artifact/Source 引用保存 SHA-256 快照。
- 暴露 `ProjectRepository.create/get/update(project, expected_revision)`；更新 SQL 必须以 `id + expected_revision` 为条件，零行更新报告并发冲突。
- 暴露 `SourceRepository.add/get` 与 `ArtifactRepository.add/get/list_for_project`；重复 UUID 或 Artifact `(id, version)` 失败关闭，不覆盖历史。
- 首迁移创建 projects、sources/source_excerpts、artifacts 及其 upstream/citations/current pointers、jobs、reviews；jobs 只冻结 ECC-019 所需列：UUID、project UUID、kind、payload JSONB、status、attempt/max_attempts、available_at、lease_owner/lease_expires_at、last_error、created/updated_at。
- 迁移采用按编号排序的纯 SQL 文件和一个 Python runner；runner 在事务内维护 `schema_migrations`，重复执行无副作用，不引入 Alembic。

## 实施要求

- Repository 接收现有 `Database`，所有写入显式事务化，不把 psycopg 类型泄漏到领域模型。
- JSONB 解码后重新经过领域构造器校验；未知枚举、非 UTC/损坏摘要不得静默返回。
- 测试使用 `TEST_DATABASE_URL` 的独立数据库；未设置时仅跳过 PostgreSQL 集成用例，不把 SQLite 作为兼容路径。

## 验收标准

- 空数据库可迁移且再次迁移无变化；Repository 完整 round-trip 冻结对象。
- 乐观并发冲突、重复不可变产物、损坏持久化值均有失败测试。
- 当前产物指针引用已存在 Artifact，删除/覆盖历史产物不可用。

## 验收命令

```bash
.venv/bin/ruff check apps/common packages/domain tests/test_repositories.py
.venv/bin/mypy apps/common packages/domain
TEST_DATABASE_URL="$TEST_DATABASE_URL" .venv/bin/python -m pytest tests/test_repositories.py
./scripts/check-docs.sh
git diff --check
```

## 工作量、风险与回滚

边界为一至两天。风险是首迁移和映射错误；回滚应用提交并仅在未承载数据的开发库删除新表，已有数据环境必须追加迁移。缺少可用 PostgreSQL 时不得标记完成。
