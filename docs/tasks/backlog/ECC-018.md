# ECC-018：确定性 Fake 适配器

## 目标与背景

为普通测试提供不联网、不消费付费额度、输出可复现的 Provider 与 Publisher Fake。

## 文件范围

- 允许：`packages/providers/fake.py`、`packages/providers/__init__.py`、`packages/publishers/fake.py`、`packages/publishers/__init__.py`、`tests/test_fake_adapters.py`、本任务与 handoff。
- 禁止：领域契约、应用、数据库、Worker、真实 SDK、配置、CI/部署与 ADR。

## 输入与冻结接口

- 实现 ADR-004 的 `Provider.generate` 和 Publisher 的 `validate/publish/status/metrics`，不扩展协议。
- Provider 由构造参数 `created_at`、`created_by` 和 `storage_root` 控制环境差异；相同规范化 GenerationRequest 生成相同 Artifact UUID、SHA-256、相对路径和 consumed_units，并写入确定性 UTF-8 JSON 产物。
- Publisher 以 Publication 的不可变 idempotency_key 保存内存结果；同键同请求返回同一 external_id，同键不同请求抛 `AdapterContractError`；未知 publication 状态为 `PENDING`，指标使用构造时固定 `captured_at`。

## 实施要求

- 规范化 JSON 使用排序键与固定分隔符；禁止读取网络、系统时间、随机数或环境密钥。
- 可通过构造参数注入一次性 `RetryableError` 与永久失败，供 Worker/E2E 验证；默认路径始终成功。
- 所有产物路径必须通过 Artifact 的安全相对路径校验。

## 验收标准

- 相同输入跨两个 Fake 实例产生字节级一致结果，不同关键输入产生不同摘要。
- Publisher 重复发布不产生第二个 external_id；冲突幂等键失败关闭。
- 可重试和永久失败注入各有测试，且无外部请求。

## 验收命令

```bash
.venv/bin/ruff check packages/providers packages/publishers tests/test_fake_adapters.py
.venv/bin/mypy packages/providers packages/publishers
.venv/bin/python -m pytest tests/test_fake_adapters.py tests/test_adapter_contracts.py
./scripts/check-docs.sh
git diff --check
```
