# ECC-022：来源证据与风险规则

## 目标与背景

实现 M1 事实优先的最小失败关闭规则，使进入审核的事实卡片必须引用当前、可验证的 Source excerpt。

## 文件范围

- 允许：`packages/pipeline/evidence.py`、`packages/pipeline/__init__.py`、必要的 `packages/domain/errors.py` 导出、`tests/test_evidence_rules.py`、本任务与 handoff。
- 禁止：领域模型字段、Repository、API、Worker、Web、供应商、CI/部署与 ADR。

## 输入与冻结接口

- 暴露 `validate_artifact_evidence(artifact, sources_by_id) -> EvidenceReport`；报告含 `valid: bool` 与排序稳定的 `issues`，issue 固定 `{code, source_id?, excerpt_id?}`。
- FACT_CARD 与 SCRIPT 必须至少一条 citation；其他 ArtifactKind 可无 citation。每条 citation 的 source/excerpt 必须存在，且 `source_sha256` 等于当前 Source.sha256。
- issue code 固定为 `citation_required`、`source_missing`、`excerpt_missing`、`source_digest_mismatch`、`duplicate_citation`；任何 issue 使 valid=false。

## 实施要求

- 规则为纯函数，不访问数据库、网络或系统时间；调用者负责从 Repository 装载 Source。
- 去重键为 `(source_id, excerpt_id, source_sha256)`；输出按 code/source/excerpt 排序，便于确定性测试与 Fake E2E。
- 不实现可信来源抓取、自然语言事实识别、敏感词库或模型评分。

## 验收标准

- 有效引用通过；无引用、缺失来源/片段、摘要漂移、重复引用均失败关闭。
- 非事实类产物无引用时通过；输入和报告不可被函数修改。
- 测试不依赖 PostgreSQL 或外部服务。
