# ECC-023：Fake 端到端纵向切片

## 目标与背景

集成 M1 组件，证明项目可经确定性 Fake 生成带证据的事实卡片、失败恢复、进入审核并由人工批准，且血缘可追溯。

## 文件范围

- 允许：`packages/pipeline/**`、`apps/api/**`、`apps/worker/**`、必要的追加迁移、`tests/e2e/**`、`tests/test_m1_vertical_slice.py`、`docs/runbooks/local-development.md`、本任务与 handoff。
- 禁止：Web、真实供应商/发布渠道、部署/Actions、已冻结领域接口与 ADR。

## 输入与冻结接口

- 新增 `POST /projects/{id}/generate`，只允许 draft 或 generation-failed 项目；原子转换到 generating 并 enqueue 固定 kind `generate_fact_card`，返回 202 `{job_id,project_id,status}`。
- handler 从 payload 读取 project ID、Source IDs、模板版本和预算，调用 Fake Provider，验证 ECC-022 evidence，持久化不可变 Artifact、更新 FACT_CARD 当前指针，并转换到 review_required。
- 重复同一 `Idempotency-Key` 返回原 job；同键不同请求 409。RetryableError 由 ECC-019 重试，永久/证据错误将项目转换为 failed；恢复创建新 Job 和 Artifact 版本，不覆盖历史。

## 实施要求

- E2E 使用真实 PostgreSQL、临时 artifact 根目录、Fake Provider 和 API TestClient；禁止网络和真实凭据。
- 数据库写入、Job 成功和项目状态/当前指针更新必须具有明确事务边界，崩溃后不得出现 succeeded Job 指向缺失 Artifact。
- 不集成发布、媒体、Web 或定时调度。

## 验收标准

- 成功链路达到 approved，Artifact 可回溯 Source/excerpt/摘要与上游，生成字节可复现。
- 一次可重试失败恢复成功；永久证据失败进入 generation failed，恢复后产生新版本。
- 重复生成请求不重复排队，进程重启后未完成 Job 可恢复。

## 验收命令

```bash
.venv/bin/ruff check apps packages tests/e2e tests/test_m1_vertical_slice.py
.venv/bin/mypy apps packages
TEST_DATABASE_URL="$TEST_DATABASE_URL" .venv/bin/python -m pytest tests/e2e tests/test_m1_vertical_slice.py
POSTGRES_PASSWORD=validation-only ./scripts/verify.sh
git diff --check
```

## 工作量、风险与回滚

边界为一至两天，只做一条 FACT_CARD 纵向切片。跨模块事务与恢复为高风险；若依赖接口不完整，应停止并回到对应前置任务，不在集成任务中另造兼容接口。回滚路由、handler 和追加迁移，保留已写不可变产物供审计。
