# ECC-024：本地验证与 CI 格式门禁对齐

## 目标与背景

让本地统一验证和 GitHub Python 门禁执行同一套 Ruff 格式检查，避免开发者通过本地验证后才在 CI 发现格式差异。

## 文件范围

- 允许：`scripts/verify.sh`、`.github/workflows/pr-fast.yml`、`.github/workflows/ci.yml`、必要的 Shell 测试、`docs/runbooks/iteration.md`、本任务与 handoff。
- 禁止：应用、领域包、迁移、依赖版本、部署/发布工作流与 ADR。

## 输入与冻结接口

- Python 格式门禁固定为 `ruff format --check .`，必须与现有 `ruff check .` 分开执行。
- `scripts/verify.sh` 在检测到 ruff 时顺序执行 format check 和 lint；PR fast 与完整 CI 调用相同脚本或相同两条命令，不复制不同路径集合。
- 仅检查，不自动重写文件；缺少 ruff 时保留当前本地可选工具语义，CI 安装依赖后必须执行。

## 实施要求

- 更新迭代 runbook，明确修复命令 `ruff format .` 与提交前检查命令。
- 若现有代码不符合格式，应在本任务内做最小机械格式化；不得夹带行为修改。
- 工作流保持现有并发取消、缓存、路径过滤与必需检查名称。

## 验收标准

- 人为制造格式差异时本地和 CI 入口均失败；格式修复后均通过。
- Shell/YAML 静态检查和全量本地验证通过，现有检查未被移除。
- diff 中无应用行为变化。

## 验收命令

```bash
bash -n scripts/verify.sh
POSTGRES_PASSWORD=validation-only ./scripts/verify.sh
./scripts/check-docs.sh
git diff --check
```

## 工作量、风险与回滚

边界为半天。风险是必需检查名称或路径过滤漂移；不得重命名现有 GitHub Check。回滚本任务提交即可恢复原门禁。
