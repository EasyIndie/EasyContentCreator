# ECC-026：Job handler 原子终结协议

## 目标与背景

落实 ADR-005，将 Worker 与生成 handler 全量切换为 handler 拥有终态事务，关闭 Artifact、项目状态与 Job 分事务提交造成的崩溃窗口。

## 文件范围

- 允许：`packages/pipeline/jobs.py`、`packages/pipeline/generation.py`、`packages/pipeline/__init__.py`、`apps/worker/**`、必要的 `003_*.sql` 追加迁移、对应 Job/Worker/事务测试、本任务与 handoff。
- 禁止：`001_initial.sql`、`002` 历史迁移、冻结领域模型、API、Provider/Publisher、Web、部署/Actions 与已接受 ADR。

## 输入与接口

- JobHandler 正常返回表示 handler 已自行提交 Job 终态；Worker 不再自动调用 `succeed`。
- `JobStore.require_terminal(job_id) -> JobStatus` 只接受 `succeeded|failed`；handler 返回后仍为 running/queued 时抛契约错误。
- FACT_CARD handler 使用 ECC-025 reservation、Provider 请求与 citations 规则，接收 Provider 和 UTC clock 注入。
- 成功接口必须在一个事务内校验 live lease并提交 Artifact/血缘/citations、current pointer、项目 `review_required` 和 Job `succeeded`。
- 永久失败接口必须在一个事务内校验 live lease并保存候选 Artifact（若存在）、保持 current pointer、项目 generation-failed 和 Job `failed`。
- `RetryableError` 必须向 Worker 传播；Worker 只调用现有 retry 排队逻辑，项目保持 generating，reservation 不变。

## 实施要求

- terminal SQL 的条件必须包含 Job ID、`status=running`、lease owner 及 `lease_expires_at > now`；失租事务不得写 Artifact、项目或 Job 终态。
- 成功/永久失败均锁定并核对 generation reservation 与项目 revision/status；Artifact identity/version 必须等于 reservation。
- 证据验证发生在终态事务提交前；ECC-022 报告任一 issue 时走永久失败事务，不得移动 current pointer。
- Worker 未知 kind 仍可直接永久 fail；已注册 handler 不允许沿用“return 后 Worker succeed”的旧路径。
- handler 返回但未提交终态按 `AdapterContractError` 失败关闭，不增加兼容 fallback。
- 文件写入先于数据库终态事务；重试复用确定性路径。进程在事务前崩溃由租约恢复，事务提交后崩溃因 Job 已终态不得再次认领。
- 数据库只保存错误分类，日志不得包含 payload、Source 正文、异常正文或密钥。

## 验收标准

- 真实 PostgreSQL 中成功终态涉及的 Artifact、血缘/citations、current pointer、项目与 Job 写入要么全部存在，要么全部不存在；不存在 succeeded Job 指向缺失 Artifact。
- 永久证据失败保存不可变候选版本、current pointer 不变、项目 failed 与 Job failed 同时可见。
- RetryableError 后只有 Job 回 queued，项目仍 generating，下一 attempt 复用同一 reservation 和版本。
- handler 返回但未提交、失租提交、事务中途注入异常均失败关闭且没有部分写入。
- 分别模拟终态事务提交前和提交后的进程崩溃：前者租约到期可恢复，后者不能再次 claim或重复 Artifact。
- PollingWorker 原有停止、心跳、未知 kind 和并发租约测试保持通过。
