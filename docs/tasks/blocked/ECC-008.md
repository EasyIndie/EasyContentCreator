# ECC-008：并行协作与交付演练

## 目标与背景

通过两个互不冲突的低风险任务验证独立 Worktree、低价模型执行、冻结接口、顺序合并、handoff、质量门禁、staging 和回滚链路。

## 子任务与接口

- ECC-009：API `GET /version`，返回 `{ "version": string, "commit": string }`。
- ECC-010：Web 获取并显示同一结构，失败时显示 `unavailable`。
- 构建信息来自 `ECC_VERSION`、`ECC_COMMIT`，默认 `dev`、`unknown`。

## 验收标准

- 两项任务在独立 Worktree 完成并包含任务文件、测试和 handoff。
- 按 API 后 Web 顺序合并，统一验证全部通过。
- GitHub 必需检查实际通过，staging 版本一致，回滚演练成功。

## 验收命令

```bash
env PATH="$PWD/.venv/bin:$PATH" POSTGRES_PASSWORD=validation-only bash scripts/verify.sh
bash deploy/tests/test-deploy.sh
git diff --check
```

## 阻塞与解除条件

- GitHub remote 已配置，远程 CI、Security、Docs Check 和 GHCR 镜像发布已经验证。
- 尚未配置单台 Linux staging 及其 SSH、部署目录和备份目录 Secrets，无法执行 Smoke Test 与真实回滚。
- 配置服务器与 Environment Secrets 后设置 `STAGING_ENABLED=true`，执行 staging Smoke Test 和真实回滚即可解除。
