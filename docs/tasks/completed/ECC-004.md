# ECC-004：建立应用工程脚手架

## 目标与背景

建立 FastAPI、数据库轮询 Worker、React Web 与共享 Python 包的最小可运行工程，不实现 M1 业务。

## 文件范围

- 允许：`apps/`、`packages/`、`tests/`、`pyproject.toml`、`.env.example`、`.gitignore`、`README.md`、本任务及其 runbook/handoff。
- 禁止：愿景、架构、路线、ADR、GitHub Actions、Compose 与部署文件。

## 输入与接口

依据 M0 计划和 ECC-004 父任务说明；API 提供独立存活与数据库就绪探针。

## 实施要求

- Python 配置来自环境变量，密钥不入库。
- Worker 只建立轮询生命周期，不定义 M1 任务表或业务。
- Web 只展示 API 健康状态。

## 验收标准

- Python 模块可编译，API 和 Worker 具备基础单元测试。
- Web 可执行 lint、测试与生产构建。
- 本地启动方式有可重复文档。

## 验收命令

```bash
python -m compileall apps packages tests
ruff check . && mypy && pytest
cd apps/web && npm run lint && npm test && npm run build
```

## 风险与回滚

脚手架不包含迁移与业务模型，可通过回退本任务提交整体撤销。

## 执行记录

- 结果：完成最小 API、Worker、Web、共享包目录与本地开发说明。
- 测试：Python Ruff、Mypy、4 项 Pytest，Web ESLint、1 项 Vitest 与生产构建均通过；见 handoff。
- 偏差：前置 ECC-003 尚未出现在本 worktree，未据此引入任何未冻结业务接口。
- 后续：M1 定义任务认领协议和数据库迁移后再扩展 Worker。
