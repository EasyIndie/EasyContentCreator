# ECC-009：API 构建版本接口

## 目标与背景

作为 `ECC-008` 并行协作演练的 API 子任务，提供可由构建环境注入的版本信息，供部署验证和 Web 展示使用。

## 文件范围

- 允许：`apps/common`、`apps/api`、`tests`、本任务文件及对应 handoff。
- 禁止：Web、CI、Compose、架构及已接受 ADR。

## 输入与接口

`GET /version` 的冻结响应为 `{ "version": string, "commit": string }`。值分别来自 `ECC_VERSION` 和 `ECC_COMMIT`，缺省为 `dev` 和 `unknown`。

## 实施要求

- 复用 API 的 `Settings` 依赖注入。
- 使用严格响应模型限定公开字段。
- 测试缺省值和环境变量覆盖。

## 验收标准

- `/version` 始终返回 HTTP 200 和两个冻结字段。
- 未注入构建信息时返回 `dev`/`unknown`。
- 注入环境变量时准确返回对应值。

## 验收命令

```bash
ruff check apps/common apps/api tests
mypy apps packages
python -m pytest
git diff --check
```

## 风险与回滚

该接口只读且不访问数据库；回滚本任务提交即可移除。不得在版本字段中注入密钥。

## 执行记录

- 结果：完成配置字段、`GET /version` 和两类接口测试。
- 测试：全部验收命令通过，6 项测试通过，详见 handoff。
- 偏差：无。
- 后续：父任务 `ECC-008` 合入 API 后，可由 Web 子任务消费冻结响应。
