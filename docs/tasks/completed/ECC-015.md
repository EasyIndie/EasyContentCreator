# ECC-015：冻结 M1 领域模型与适配器契约

## 目标与背景

为 M1 的数据库、Worker、供应商适配器与控制台提供无基础设施依赖的公共 Python 契约，落实 ADR-001 与 ADR-002。

## 文件范围

- 允许：`packages/domain/**`、`packages/pipeline/**`、`packages/providers/**`、`packages/publishers/**`、`tests/test_domain_*.py`、`tests/test_*_contracts.py`、`docs/architecture.md`、`docs/roadmap.md`、`docs/decisions/ADR-004-domain-contracts.md`、本任务与交接文件。
- 禁止：`apps/**`、`migrations/**`、部署和 GitHub Actions。

## 输入与接口

- `ADR-001` 的 PostgreSQL Job 租约边界。
- `ADR-002` 的不可变 Artifact 与适配器边界。
- 架构文档定义的项目状态和五个供应商/发布接口。

## 实施要求

- 使用不可变、严格类型化的数据类定义项目、来源、产物引用、生成与发布请求结果。
- 项目状态转换必须显式校验，禁止跳过审核发布。
- 产物版本与血缘字段必须足以支持后续存储和失效传播。
- Provider 与 Publisher 仅依赖项目自有协议，不引入外部 SDK。
- 区分可重试、永久、契约和状态转换错误。

## 验收标准

- 合法状态转换通过，非法转换失败关闭。
- 不可变对象不能原地修改；产物摘要、上游与来源引用可表达。
- Provider/Publisher Fake 可在后续任务中仅依赖冻结协议实现。
- 测试覆盖成功和关键失败路径。

## 验收命令

```bash
.venv/bin/ruff check packages tests
.venv/bin/mypy packages
.venv/bin/python -m pytest tests/test_domain_contracts.py tests/test_adapter_contracts.py
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

公共契约变更会影响多个后续任务，因此本任务合并前不并行实现依赖方。回滚为撤销本任务提交；合并后破坏性变更需新 ADR。
