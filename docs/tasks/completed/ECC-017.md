# ECC-017：PostgreSQL schema 与领域 Repository

## 目标与背景

为冻结的 ContentProject、Source、Artifact 建立首个 PostgreSQL 持久化切片，并为后续 Job、审核和证据规则提供向前兼容表结构。

## 文件范围

- 允许：`migrations/**`、`packages/domain/repositories.py`、`packages/domain/__init__.py`、`apps/common/database.py`、`tests/test_repositories.py`、`tests/conftest.py`、本任务与 handoff。
- 禁止：`apps/api/**`、`apps/worker/**`、Provider/Publisher、Web、CI/部署与已接受 ADR。

## 输入与冻结接口

- 遵守 ADR-004：枚举为字符串、时间为 UTC、元数据为 JSONB、Artifact/Source 引用保存 SHA-256 快照。
- 暴露 `ProjectRepository.create/get/update(project, expected_revision)`；更新以 `id + expected_revision` 为条件。
- 暴露 `SourceRepository.add/get` 与 `ArtifactRepository.add/get/list_for_project`，不可变实体不覆盖历史。
- 首迁移建立 projects、sources/source_excerpts、artifacts、血缘、引用、current pointers、jobs 和 reviews。
- 迁移按编号执行纯 SQL，并在事务内维护 `schema_migrations`。

## 实施要求

- Repository 使用现有 `Database`，写入显式事务化，读取结果重新经过领域构造器。
- PostgreSQL 约束验证枚举、摘要、引用和当前指针，触发器禁止覆盖或删除不可变历史。
- 集成测试只使用 `TEST_DATABASE_URL`，每次创建随机隔离 schema，不清理共享 schema。

## 验收标准

- 空 schema 可迁移，重复迁移无变化。
- ContentProject、Source、Artifact、血缘、引用、嵌套 JSONB 和当前指针完整 round-trip。
- 两个真实并发写入只有一个 revision 更新成功。
- 重复不可变实体、损坏历史、无效 current pointer 均失败关闭。

## 验收命令

```bash
.venv/bin/ruff check apps/common packages/domain tests/test_repositories.py
.venv/bin/mypy apps/common packages/domain
TEST_DATABASE_URL="$TEST_DATABASE_URL" .venv/bin/python -m pytest tests/test_repositories.py
./scripts/check-docs.sh
git diff --check
```

## 工作量、风险与回滚

首迁移只能在空数据库应用；合并后只能追加迁移，不能修改历史 SQL。开发库可回滚提交并删除尚未承载数据的测试 schema，已有数据环境不得删除表。
