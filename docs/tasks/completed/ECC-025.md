# ECC-025：生成请求身份与 Artifact 版本契约

## 目标与背景

落实 ADR-005，冻结 FACT_CARD 请求幂等、逻辑 Artifact ID、单调版本预留和 Source citations 规则，为 API 与 handler 提供唯一生成契约。

## 文件范围

- 允许：`migrations/002_*.sql`、`packages/pipeline/generation.py`、`packages/pipeline/__init__.py`、`packages/providers/contracts.py`、`packages/providers/fake.py`、对应 provider/pipeline/数据库测试、本任务与 handoff。
- 禁止：`001_initial.sql`、冻结领域模型、API、Worker、Publisher、Web、部署/Actions 与已接受 ADR。

## 输入与接口

- 新增不可变 `FactCardGenerationSpec`、`GenerationReservation`、canonical request hash、逻辑 FACT_CARD ID 和稳定 citations 构造。
- `GenerationRequest` 必填 `output_artifact_id` 与 `output_version`，Fake 原样写入 ArtifactRef。
- `GenerationRequestRepository.reserve_and_enqueue` 在项目行锁事务内完成幂等判断、版本预留、状态转换和 Job 插入。
- `002_generation_requests.sql` 保存请求字段、摘要、Job、Artifact reservation 和项目 revision。

## 实施要求

- source IDs 非空、不得重复并按 UUID 字符串规范排序；hash 只包含 ADR-005 冻结的四个字段。
- 同 key/同 hash 返回原 reservation；同 key/不同 hash 抛 `GenerationRequestConflict`。
- 逻辑 ID 为 `uuid5(project_id, "artifact:fact_card")`；version 同时考虑 Artifact 历史和未完成 reservation。
- citations 覆盖所有 Source 的全部 excerpts并稳定排序；空 excerpts 永久失败。
- Fake 不保留旧的自行派生 ID/version 路径，同 reservation 不同内容拒绝覆盖。

## 验收标准

- 串行与双连接并发幂等复用一个 Job/reservation。
- 异 key 并发只允许一个单活生成，不产生重复版本。
- generation-failed 后新 key 保留逻辑 ID并预留 version 2。
- Fake 跨实例字节一致，严格保留 reservation；citations 完整且稳定。
- 迁移重复执行无副作用，既有 Repository 与适配器测试保持通过。
