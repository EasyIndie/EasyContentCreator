# ECC-028：审核拒绝与生成恢复语义

## 目标与背景

落实 ADR-006，消除 reject 后无 Job 的 `generating` 状态，并证明拒绝审计、pointer 保留及新版本恢复原子一致。

## 文件范围

- 允许：`packages/domain/state.py`、审核相关 Repository、`apps/api/main.py`、对应迁移（仅确有历史数据修正时新增 `003`）、审核/API/E2E 测试、本任务与 handoff。
- 禁止：Artifact/Provider 冻结协议、Web、Job 查询 API、Compose/部署。

## 输入与接口

- ADR-006、ADR-005、ECC-020/023/025/026 handoff。
- reject 响应仍为既有 ReviewResponse；项目结果固定 `failed`、`failed_stage=generation`。

## 实施要求

- `apply_review` 单事务追加 Review 并执行 `review_required→generation-failed`，current pointer 不变。
- reject 不 enqueue；恢复必须调用既有 generate API，使用新 key 预留下一个版本。
- 旧 key 重放不恢复；拒绝/Review 插入失败必须全回滚。
- 若发现历史无 Job generating 数据，只能用追加迁移显式处理并记录数量规则。

## 验收标准

- 真实 PostgreSQL 覆盖 reject 原子性、pointer/Artifact 保留、旧 key 重放、新 key version+1、并发 reject/review 冲突。
- 不存在由审核操作产生的无 Job generating。

## 验收命令

```bash
.venv/bin/ruff check apps/api packages/domain tests
.venv/bin/mypy apps/api packages/domain
TEST_DATABASE_URL="$TEST_DATABASE_URL" .venv/bin/python -m pytest tests/test_project_api.py tests/test_m1_vertical_slice.py
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

状态语义为高风险全量切换，不保留 reject→generating 兼容路径；已应用迁移只能追加修正。

## 执行记录

- 结果：审核拒绝全量切换为 `failed`/`generation`；Review 与状态在同一事务提交，保留 current pointer 与不可变 Artifact；旧 key 仅重放原 Job，新 key 原子恢复并预留下一版本；公共状态机不再允许 `review_required → generating`。
- 测试：真实 PostgreSQL 16 下目标测试 34 项、全量测试 116 项通过，覆盖插入失败回滚、并发审核冲突、旧 key 终态重放及异摘要 409、新 key version+1、错误决策映射与无 Job generating 查询不变量；Ruff、Mypy、文档及 diff 门禁通过。
- 偏差：未新增 `003` 迁移；当前基线没有需修正的已知历史数据，运行时语义全量切换即可。
