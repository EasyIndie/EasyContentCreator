# ECC-030：Web 证据审阅界面

## 目标与背景

基于 ECC-029 冻结 API，在现有项目详情/审核界面展示 FACT_CARD、citations、Source/excerpts 与摘要校验信息。

## 文件范围

- 允许：`apps/web/**`、前端测试、本任务与 handoff。
- 禁止：后端、数据库、下载任意 Artifact 文件、审核语义。

## 输入与接口

- 只消费 ECC-029 响应；不得由前端拼接服务器路径。
- 明确 loading、empty、404/error、摘要不一致警示和键盘可访问状态。

## 实施要求

- citation 可定位到对应 Source/excerpt；显示 Source kind、URI、SHA 摘要短标识与完整可复制值。
- 审核按钮只有证据加载成功时可用；API 错误不得被当作无证据通过。

## 验收标准

- Vitest 覆盖多 Source/excerpt、缺 citation、摘要问题、网络错误与审核操作。
- 生产构建通过，窄屏可读。

## 验收命令

```bash
npm --prefix apps/web run lint
npm --prefix apps/web test -- --run
npm --prefix apps/web run build
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

前端展示不改变后端事实门禁；回滚页面变更不影响 Artifact/Review 数据。

## 执行记录

- 结果：现有项目详情已接入 FACT_CARD 证据链，按 citation 去重加载 Source，展示 Source kind、
  URI、摘要、SHA 短标识与完整值，以及可定位的 excerpt；证据 loading、empty、404、网络错误与
  摘要不一致均有独立可访问状态，证据未成功加载时审核提交保持禁用。
- 测试：Vitest 覆盖多 Source/excerpt、缺 citation、摘要漂移、404、网络错误、无 FACT_CARD、
  审核批准/驳回、冲突刷新、防重复提交，以及与 ECC-032 Job 恢复控制台同屏加载；lint、22 项
  测试、生产构建、文档及 diff 检查通过。
- 偏差：未增加 Artifact 文件读取或下载；缺 citation 属于成功加载后的醒目事实风险提示，保留
  驳回操作能力，最终事实门禁仍由后端负责。
- 后续：ECC-034。
