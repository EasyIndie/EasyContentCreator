# ECC-031：Job 错误与恢复只读 API

## 目标与背景

让操作者安全查看项目 Job、失败分类和是否可恢复，并复用既有 generate API 发起 generation-failed 恢复。

## 文件范围

- 允许：`packages/pipeline/jobs.py`、`apps/api/**`、对应 API/真实 PostgreSQL 测试、本任务与 handoff。
- 禁止：Worker payload、异常正文、Source 正文、自动重试策略、Web、迁移（无实测必要不得新增）。

## 输入与接口

- `GET /projects/{project_id}/jobs` 与 `GET /jobs/{job_id}`。
- 响应仅含 id、project_id、kind、status、attempt/max_attempts、available/created/updated 时间、`error_class` 与 `recoverable`；禁止 payload、lease owner、异常正文和密钥。
- generation recovery 继续使用 `POST /projects/{id}/generate` 新 key，不新增旁路 retry endpoint。

## 实施要求

- `last_error` 仅作为已校验安全 error_class 输出；不安全历史值降级为固定 `UnknownError`，不得原样返回。
- project ownership、稳定排序、404/422 与终态/queued/running 状态覆盖完整。
- recoverable 只在 generation-failed 且调用者可通过现有生成请求恢复时为 true。

## 验收标准

- 真实数据库证明响应和日志均无 payload/正文/secret；跨项目查询失败关闭。
- 可重试、永久失败、租约过期和 succeeded 状态显示准确。

## 验收命令

```bash
.venv/bin/ruff check apps/api packages/pipeline tests
.venv/bin/mypy apps/api packages/pipeline
TEST_DATABASE_URL="$TEST_DATABASE_URL" .venv/bin/python -m pytest tests/test_job_api.py tests/test_job_executor.py
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

错误接口是安全边界；发现无法证明安全类名时必须固定替代而非输出数据库原文。

## 执行记录

- 结果：完成安全 Job 投影、项目 Job 列表与 Job 详情 API；响应不查询或暴露 payload、租约和异常正文。
- 测试：真实 PostgreSQL 下 Job/API 与既有执行器 15 项通过，完整 Python 回归 116 项通过；Ruff、strict Mypy、文档与 diff 检查通过。
- 偏差：无迁移；恢复继续使用既有 generate API，不新增 retry 写入口。recoverable 精确绑定项目最新 generation reservation；仅失败 Job或具有当前 revision reject 审计的 succeeded Job可恢复，任意历史/非生成/不一致 Job均失败关闭。
