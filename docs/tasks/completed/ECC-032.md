# ECC-032：Job 错误与恢复 Web 控制台

## 目标与背景

在项目详情展示安全 Job 时间线、错误分类和 generation-failed 恢复表单，使操作者无需数据库访问即可诊断和恢复。

## 文件范围

- 允许：`apps/web/**`、前端测试、本任务与 handoff。
- 禁止：后端、数据库、payload/异常正文展示、浏览器自动重试。

## 输入与接口

- 只使用 ECC-031 Job 响应和既有 generate API。
- 恢复表单必须提交新 Idempotency-Key、Source IDs、template version、strict budget，并显示新 Job。

## 实施要求

- 按时间稳定展示 queued/running/succeeded/failed、attempt 和安全 error_class。
- 只有 recoverable 为 true 时显示恢复操作；重复提交保持幂等，409/422 明确反馈。

## 验收标准

- 覆盖各状态、空列表、API 失败、恢复成功/冲突/验证错误；DOM 中不存在 payload、secret 或异常正文。
- Lint、测试、生产构建通过。

## 验收命令

```bash
npm --prefix apps/web run lint
npm --prefix apps/web test -- --run
npm --prefix apps/web run build
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

Web 不创建新的恢复协议；回滚 UI 不影响 Job 或 Artifact 数据。

## 执行记录

- 结果：项目详情新增安全 Job 时间线、错误分类和仅由 `recoverable` 驱动的恢复表单；恢复复用
  generate API，并保留 Idempotency-Key 与请求字段以支持幂等重放。
- 测试：Web ESLint、16 项 Vitest 与生产构建通过，覆盖四种状态、空/错误列表、恢复成功、
  幂等重放、409/422 反馈以及 payload/secret/异常正文不进入 DOM。
- 偏差：无；未修改后端、数据库或自动重试行为。
- 后续：ECC-034。
