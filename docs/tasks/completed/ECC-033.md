# ECC-033：Compose 迁移入口与 fail-closed 验证

## 目标与背景

消除本地 Compose 启动前必须手工执行 migration 的隐含步骤，使新数据库自动按既有 runner 迁移，迁移失败时 API/Worker 不启动。

## 文件范围

- 允许：`compose.yaml`、最小迁移命令/脚本、Dockerfile（仅入口所需）、Compose/脚本测试、local runbook、本任务与 handoff。
- 禁止：修改 001/002、替换迁移框架、deploy/Actions、应用业务接口。

## 输入与接口

- 复用 `migrations.run_migrations(Database(get_settings().database_url))`。
- Compose 增加一次性 migrate service；API/Worker 依赖其 `service_completed_successfully`，Worker 继续复用统一 app image。

## 实施要求

- fresh volume 自动应用全部迁移；重复 up 无副作用。
- 注入坏 migration/无数据库时 migrate 非零，API/Worker 不得启动或报告 ready。
- 配置和日志不得输出数据库密码；不让 API/Worker 各自并发猜测迁移。

## 验收标准

- 独立 COMPOSE_PROJECT_NAME 完成 build/up、migration 表验证、health、Worker 运行和 down -v。
- 故障注入证明 fail-closed；verify 脚本包含该门禁或等价自动测试。

## 验收命令

```bash
.venv/bin/ruff check apps migrations tests scripts
.venv/bin/mypy apps migrations
.venv/bin/python -m pytest tests/e2e/test_compose_migrations.py
POSTGRES_PASSWORD=validation-only ./scripts/verify.sh
./scripts/check-docs.sh
git diff --check
```

## 风险与回滚

Compose 依赖条件跨平台敏感；必须以实际 Docker Compose 验证。只清理任务专属项目和卷。

- 结果：已完成一次性 migrate service、API/Worker 成功依赖、真实隔离 Compose 迁移门禁；验证器固定使用当前 worktree Python 模块入口并拒绝外部 editable 导入。
- 测试：rebase 到 `main@574422f` 后，真实 Compose fresh/repeat/bad migration/数据库不可达 fail-closed/health/cleanup 通过；带真实 PostgreSQL 的 Python 129 项、Compose 2 项与 Web 9 项通过，Ruff、strict Mypy、docs/diff 全部通过。
- 偏差：按准出核心将 `scripts/verify.sh` 及其最小工具链验证脚本纳入本任务范围；Compose 测试使用 marker 在统一验证中独立执行一次，未修改 001/002、deploy 或 Actions。
