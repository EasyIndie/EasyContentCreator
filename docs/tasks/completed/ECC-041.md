# ECC-041：素材授权与安全导入边界

## 目标与范围

实现本地素材导入、license/rights manifest、摘要与 artifact-root 安全边界。只改 media/providers/domain/tests/runbook/docs；不做网页抓取、浏览器自动化或渠道发布。

## 验收

- 拒绝绝对/穿越/NUL/symlink escape、MIME 伪装和摘要漂移；导入为不可变相对路径。
- 每个外部素材有来源、许可类型/范围/到期状态；unknown/expired 阻塞 QC。
- 临时写、原子 rename、同摘要恢复/异摘要冲突与日志脱敏测试通过。

## 执行记录

- 结果：新增受控 import root 到 artifact root 的 `LocalAssetImporter`。根目录以下所有来源父目录、目标父目录、
  attempt、锁和最终文件均通过可信 dirfd 逐级以 `O_DIRECTORY | O_NOFOLLOW` / `openat` 语义访问；锁内
  重走目标父目录并比对 inode。最终文件以 hard-link publish 实现原子 no-replace，`EEXIST` 后只通过安全
  fd 复核 regular、单硬链、摘要和解码结果；同摘要恢复复用，异摘要或非协作竞态失败关闭。
- 内容验证：JPEG/PNG/MP4/WAV/MP3 先做完整容器/EOF 边界校验，再用单机 Linux/macOS 白名单绝对路径
  `ffprobe` 与 `ffmpeg`、固定 argv、无 shell、超时和受限错误输出完成真实 probe/全量解码；损坏、伪装、
  尾随 polyglot 均不落最终路径。新增 `asset_rights_v1` manifest 契约，并拒绝公开 provenance URI 的
  query/fragment，避免凭据进入审核 metadata。
- 测试：25 项目标测试覆盖路径/NUL/symlink、摘要、损坏/polyglot、parent swap、目标抢占、多硬链、
  原子 no-replace、恢复/冲突、错误脱敏、rights blocker 与 provenance URI；Ruff、strict Mypy、全量
  非 Compose Python、docs 和 diff 检查通过。
- 偏差：未修改 ECC-036 冻结的 PipelineRun/StepRun/LogicalArtifactRef；未实现 Web、FFmpeg、网页抓取、
  数据库或发布能力。
- 后续：ECC-043 QC 将 `AssetManifest.rights_issues()` 的稳定 issue code 投影为 blocker。reservation-aware
  StepProducer adapter 仍归 ECC-038/后续集成；唯一合法接入是由冻结 reservation 生成 destination，成功
  文件发布后再由 live-lease terminal transaction 提交 Artifact/StepRun/Job，不得另建无 reservation 路径。
